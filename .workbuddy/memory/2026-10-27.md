## Wrye Bash + MO2 集成问答（用户实际用法）
- 用户用 **MO2 管理 Skyrim SE 整合包**，希望从 MO2 启动 Wrye Bash 来改/管 mod 列表。
- 结论要点（已用源码 `bash/barg.py`、`bash.py:575 in_mo2_vfs()`、`gui/doc_viewer.py:67` 核对）：
  1. **必须**把 WB 作为 MO2 的 executable 启动，才能跑在 MO2 的 VFS 里看到整合包；直接双击 WB 的 exe 只会看到真实（未 mod）的 Data。
  2. WB 安装位置无硬性要求，建议放在 MO2/游戏目录之外的中立文件夹（如 `C:\Wrye Bash`），**不要**装进 MO2 的 `mods` 或游戏 `Data` 目录（会被当成 mod/污染）。
  3. MO2 添加：编辑 Executables → Add from file → 选 `Wrye Bash.exe`；推荐设「Create Files in Mod instead of Overwrite」指到一个专用空 mod（如 `Bash Patch Output`）避免产物落进 Overwrite。
  4. 命令行：`-o <游戏根目录>` = `--oblivionPath`（强制游戏路径），源码确认；`-p <路径>` 可指定 WB 自身设置存放目录（进阶）。
  5. 构建产物（`Bashed Patch, 0.esp` + `.log`）写入真实 Data，被 MO2 拦截→落 Overwrite 或指定 mod；**必须**置于加载顺序最末尾且保持激活。
  6. WB 在 MO2 下只做「重建 Bashed Patch + 设 Bash Tags + 看冲突」；装包/启停 mod 仍在 MO2 做。源码显示 MO2 VFS 下 WB 的帮助文档查看器自动禁用（正常现象）。
