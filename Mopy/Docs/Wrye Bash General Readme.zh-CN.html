简介返回顶部

Wrye Bash 是一款专为基于 Bethesda Creation 引擎开发的游戏设计的强大模组管理工具。其功能包括：

  • 模组安装与冲突管理工具
  • 插件加载顺序管理器
  • 提升了模组兼容性。
  • 通过自动合并兼容的模组，取消255个插件的限制
  • .ini文件与设置文件的调整管理
  • 截图管理
  • 还有更多更多。

术语表返回顶部

针对Creation引擎游戏的模组开发，一直存在着术语混乱的问题。下表列出了在处理模组时常用的一些术语。

  • 游戏这就是Wrye Bash正在管理的游戏，也是上述列表中的其中之一。
  • EGS指从 Epic Games 商店购买的游戏。
  • GOG平台指从 GOG.com 购买的游戏。
  • Windows应用商店指通过 Windows 商店安装的游戏。这类游戏也可被称为 Game Pass、Xbox 应用或 Microsoft 商店游戏。
  • 游戏崩溃是“Crash To Desktop”的缩写，用于描述游戏崩溃的情况。
  • DLC内容指该游戏的任何官方可下载内容。
  • 模组指对游戏进行的任何非官方用户自制修改。
  • 模组作者指对游戏进行修改的人。也可指那些参与开发供模组制作者和/或用户使用的工具的人。
  • ESM（区分大小写）或标记有ESM标签的文件指游戏将其视为此类文件的任何文件。大师级对于《辐射4》之前的游戏，唯一重要的就是文件中的ESM标志。而对于较新的游戏，则是带有特定扩展名的文件。.esm无论是否设置了相应标志，它们都会被视为主控程序。这些程序会在所有 ESP 之前加载（见下文）。Elder Scrolls Master 是其缩写形式。
  • .ESM文件（区分大小写）指的是具有该扩展名的文件。.esm有关它们在不同游戏中的表现说明，请参阅上文中的 ESM 条目。
  • ESP/ESL/ESM（不区分大小写）指任何具有该名称的文件。.esp扩展模块。它是“Elder Scrolls Plugin”的缩写。
  • ESM（区分大小写）指设置了名为 ESL 标志的标志的任何文件。具有该扩展名的文件.esl无论是否设置了相应标志，它们都会被视作 ESL 插件。目前只有《辐射4》和《上古卷轴5：特别版》支持此类插件。可被标记为 ESL 的插件存在一定的限制。它们不会占用常规的加载顺序位置，因此理论上最多可以加载 4096 个 ESL 插件。
  • ESM（区分大小写）指的是具有该扩展名的文件。.esl这些内容会自动获得 ESL 和 ESM 标记。目前仅有《辐射4》与《上古卷轴5：特别版》支持它们。
  • ESU（不区分大小写）指任何具有该名称的文件。.esu扩展程序。这类属于非官方插件，被xEdit所使用，其全称为Elder Scrolls Update。
  • 叠加层指的是《星际边境》中引入的一个标志，用于将插件标记为叠加插件叠加插件不会占用加载顺序槽位，因此你可以加载无限数量的此类插件。不过它们也有一些限制：这类插件不得包含新记录（只能用于覆盖现有内容），并且必须至少有一个主插件。
  • 插件指上述任何一种文件类型。
  • 大师级指其他插件为正常运行所依赖的任何插件。（它也可以指 ESM 文件，因为过去只有 ESM 文件才能作为主插件，直到模组作者找到了将 ESP 文件也用作主插件的方法。本文档不会采用后一种定义。）

  • 冲突当两个不同的模组试图修改同一个游戏变量或资源时就会发生冲突，这些变量或资源可以是游戏中的特定对象、脚本或纹理等任何内容。冲突可能会引发各种问题，比如游戏崩溃或存档损坏，但它们并非必然有害，实际上大多数模组的开发正是基于有意制造的冲突而实现的。
  • 资源冲突当两个模组在相同位置包含不同的文件时，就会发生这种情况：其中一个模组的文件会覆盖另一个模组的文件。此类冲突可以通过调整模组的安装顺序来解决。
  • 数据冲突当两个模组插件同时修改相同的游戏数据时，就会发生这种情况。此类冲突可以通过调整插件的加载顺序或制作补丁来解决。
  • BSA模组这些都是贝塞斯达软件公司的存档资料。.bsa (除《辐射4》之外的所有游戏) 或.ba2 (《辐射4》）文件扩展名。它们可用于存储纹理和网格等资源文件。
  • ITM物品与主记录完全相同，也就是说，某个插件中的数据与该插件主记录中对应数据一致。这通常属于一种意外的编辑错误，被称为恶意修改这会破坏其他那些要求相关记录具有特定值、但其值又被 ITM 记录覆盖的模组的正常功能。
  • UDR文件为未删除且已禁用的引用。已删除的引用可能会导致程序崩溃，可通过先将其恢复再禁用来避免此问题。这是一种脏污 编辑请注意，该缩写并非指被删除的引用本身，而是指其已修复后的对应内容。例如：扫描 UDR 文件将会扫描已删除的引用，而不会扫描未被删除或被禁用的引用。BOSS/LOOT功能会显示某个插件的UDR数值，该数值实际上就是可修复的已删除引用数量。

安装返回顶部

安装 Wrye Bash 最简单的方法是使用安装程序，因为它会自动安装 Wrye Bash 及其依赖项。注意：如果您想要管理 Windows 商店中的游戏（因为其安装程序不支持也无法处理 Windows 商店游戏），或因其他原因希望手动安装 Wrye Bash，请阅读以下说明。

注意：Wrye Bash 有两个版本：Python 版和独立版。其实它们是同一个程序，但独立版的依赖项更少，因此更适合大多数人使用。

Windows Vista、7、8及10系统用户：Windows的用户账户控制功能可能会干扰Wrye Bash及其他工具的正常运行。请参阅相关说明。文件权限解决方案部分。

卸载返回顶部

能否轻松移除 Wrye Bash 取决于你在管理修改后的游戏时对其使用的频率。

  • 如果您使用了 Bashed Patch，那么在卸载 Wrye Bash 之前，必须先从游戏存档中移除与之相关的所有依赖项，以避免出现游戏内问题。具体而言，这取决于 Bashed Patch 中包含了哪些内容，有时几乎无法完成此项操作。
  • 如果您使用 BAIN 来管理已安装的模组，就需要准备一个合适的替代管理系统。因为虽然卸载 Wrye Bash 并不会删除您的模组，但您将无法再使用 BAIN 的冲突解决功能。
  • 如果您使用了通过 Wrye Bash 进行的任何 INI 配置调整，就需要记下自己做了哪些修改。虽然卸载 Wrye Bash 并不会撤销这些调整，但您将无法再查看之前的配置记录或默认值。
  • 如果使用“人物”标签页，您需要在 Wrye Bash 之外记录有关人物的信息及其业力值。

如果以上情况均不适用于您，或者在针对适用的情况采取了必要措施后，您可以通过运行卸载程序来卸载 Wrye Bash（前提是您是通过安装程序安装的），或者如果您是手动安装的，则可以删除相应的文件和文件夹。

  • [Game]\Mopy
  • [Game]\Data\Bash Patches- 如果您已导出了任何想要保留的CSV文件，请对它们进行备份。
  • [Game]\Data\BashTags- 如果您手动创建了任何想要保留的标签文件，请对其进行备份。
  • [Game]\Data\Docs
  • [Game]\Data\INI Tweaks
  • Documents\My Games\[Game]- 仅删除BashProfiles.dat, BashProfiles.dat.bak, BashSettings.dat, BashSettings.dat.bak文件以及Saves\Bash文件夹。
  • [Game] Mods（对于大多数游戏，位于[游戏名称]所在文件夹内， 在Documents\Wrye Bash适用于 Windows 商店游戏）- 该功能Bash Installers该文件夹用于存储通过 BAIN 安装的模组。

在 BAIN 中，各软件包的安装顺序非常重要，因为它决定了在资源冲突时哪些软件包的文件会被优先安装。可以通过左键点击来指定软件包的安装顺序。订购列标题。如果有两个软件包试图安装相同的文件，那么列表中后安装的软件包所对应的文件将会覆盖先安装的软件包中的对应文件。例如，安装顺序为06的软件包中的文件会覆盖安装顺序为04的软件包中的冲突文件。需要注意的是，安装顺序较高的软件包在列表中显示的位置较靠下，这可能会让人误以为它们位于“下方”。

一个包内的子包顺序遵循与包相同的规则。在子包列表中位置较靠后（编号较小）的已检查子包，会覆盖那些位于列表前面（编号较大）且内容存在冲突的子包。

Wrye Bash会在其中显示你已安装的插件。模组标签页。此处显示了已安装插件的加载顺序，Wrye Bash 会用带勾的复选框标记这些插件。该顺序非常重要，因为它决定了在插件冲突时哪个插件会“胜出”——即后加载的插件会覆盖那些处理相同功能的插件。列表中后加载的模组在“加载顺序”一栏中的数值会更高，一旦与先加载的模组（数值较低）发生冲突，后者就会被后者取代。加载顺序与BAIN的安装顺序并非同一概念！安装顺序决定了在文件冲突时，哪个包的文件会覆盖其他包的文件。

虽然“加载顺序”通常指的是资源的加载先后顺序，但激活状态插件方面，所有已安装的插件都有指定的加载顺序。在《Oblivion》、《Nehrim: At Fate's Edge》、《Fallout 3》以及《Fallout: New Vegas》中，加载顺序取决于插件的修改时间；而在《Skyrim》与《Enderal: Forgotten Stories》中，则遵循社区共同约定的文本文件标准；至于《Fallout 4》及之后的所有游戏，会将所有已安装的插件列在plugins.txt文件中，并用星号标记出处于活跃状态的插件。*例如，即便某些插件处于非激活状态，Bash 仍需要遵循插件加载顺序，这样才能在 Bashed Patch 中正确合并这些非激活的模组。

合并插件返回顶部

仅包含特定类型数据记录的插件可以合并到 Bashed Patch 中。这样一来，这些插件就可以被禁用，从而释放加载顺序中的空间。

如果是要合并插件，无需先启用这些插件即可操作。实际上，在使用 BASH 工具进行合并时：1）会要求你事先关闭它们；2）即便你拒绝了该提示，一旦生成了 Bashed Patch，这些插件仍会被自动关闭。因此，在合并插件时，请在构建之前先将它们置于未启用状态，然后在 Bashed Patch 的构建对话框中选择合并它们。不必担心，以这种方式合并的插件依然能像预期那样被其他补丁工具正常处理。

文件权限返回顶部

如果您使用的是 Windows Vista 或更高版本，UAC 安全功能可能会妨碍 Wrye Bash（及其他模组程序）正常运行。对于 Windows 商店下载的游戏，没有相应的解决方法；如果出现错误，必须以管理员身份启动该程序（解决方案 4）。针对此问题，共有四种常见的解决办法：

  1. 将游戏安装在外部目录中。程序文件目录或者程序文件（x86）UAC会防止对这些文件夹进行未经授权的修改，因此将游戏安装在这些文件夹之外，就能使其脱离UAC的监控范围，从而更轻松地使用模组。Steam用户可以使用相应工具来移动自己的Steam安装目录及游戏文件。这些说明.
  2. 关闭用户账户控制功能。可通过“控制面板”来实现，这样就能让整个电脑都停止使用用户账户控制功能。是否在没有风险的情况下这么做，以及是否认为现有的安全措施已经足够，由您自行决定。
  3. 奖励给自己完全控制对游戏安装文件夹的权限。这样你就可以在保持UAC处于激活状态、监控未被运行的程序所做的任何修改的同时，进行任意编辑；同时也不必将游戏重新安装到其他位置。
  4. 无需操作。Wrye Bash 会自动检测是否需要以管理员身份运行，并弹出包含若干选项的对话框。
    1. 以管理员身份启动 Wrye Bash：这样就能赋予它完整的管理员权限，使其无需额外操作即可正常运行，但有一个例外情况：
      • 您无法将压缩文件拖放到安装程序窗口中，以便将其移动或复制到 BAIN 中。这是因为非管理员进程（如 explorer.exe）不允许以这种方式与管理员进程（Wrye Bash）进行通信。
    2. 正常启动即可。这样无需管理员权限就能启动 Wrye Bash。
      • 许多需要管理员权限的操作都会触发UAC提示框。常见的包括：
        • 首次启动 Wrye Bash 时，根据其需要创建的目录数量不同，该过程大约会重复 4 到 6 次。
        • 在重新生成 Bashed Patch 时，需要执行两次操作：一次针对 Bashed Patch 本身，另一次针对其对应的 README 文件。
        • 在“安装程序”选项卡中，那些需要修改游戏数据文件夹的安装、卸载、退火以及其他操作。
        • 在关闭程序时，如果“Bash 安装程序”文件夹与“Bash 模组数据”文件夹处于 UAC 保护状态，系统可能会多次提示您将各种 .dat 文件保存到这些文件夹中。
      • 有部分动作是被限制的：
        • 将文件保存到受 UAC 保护的区域：Windows 不允许“保存文件”对话框选择位于 UAC 保护文件夹内的目标位置。
        • 隐藏功能：Wrye Bash 无法取消对已隐藏模组的隐藏处理。同时，它也不会主动将模组隐藏起来。要实现这两项功能，都需要重新命名模组文件。
        • 那些需要管理员权限的其他操作可能尚未有对应的解决方案。请注意，在受 UAC 保护的目录中以非管理员身份运行时出现的任何错误，很可能都无法得到修复。请采用其他替代方案来解决这些错误。
    使用某些命令行参数启动 Wrye Bash 即可避免出现此对话框：
    • --no-uac：始终以普通模式启动，无需管理员权限
    • --uac：如需的话，始终以管理员身份启动。

对于那些希望选择第三种选项并为自己……的人完全控制关于权限，以下是相关指南：

  1. 右键点击您想要更改权限的文件夹，然后选择属性.
  2. 在属性，选择安全性点击该选项卡，然后进行操作。编辑……点击该按钮。可能会出现 UAC 提示，直接允许即可继续。
  3. 在……中群组或用户名在框中选择。用户选项。
  4. 在下方框中，选中对应选项的复选框。完全控制在……中允许选择列。按下“确定”退出。如果出现 UAC 提示，同意该更改即可。
  5. 在……中属性在窗口中选择“确定”即可退出。现在您应该已获得了对所选文件夹的完全控制权限。

如果您的游戏是通过 Windows 商店或 Xbox 应用安装的 Windows 商店游戏，那么还需要处理额外的权限问题。

  1. 默认情况下，Wrye Bash会使用另一个可写路径来存储您的安装程序以及这些安装程序的元数据。My Documents\Wrye Bash文件夹。
  2. 使用 Wrye Bash 可能需要为插件和/或 BSA 重新设置日期。遗憾的是，目前我们尚无在非管理员模式下执行此操作的方法，因此要完成这些操作，您必须以管理员身份运行 Wrye Bash，或者授予相应权限。完全控制与游戏文件夹的处理方式相同。具体而言，《Oblivion》需要定期执行此操作，以便为加载顺序配置更新插件日期。后续版本的游戏通常无需如此操作，因此大多可以在非管理员模式下运行，且无需更改文件权限。
